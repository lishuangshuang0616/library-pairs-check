# v0.6 深测序丰度证据

## 行为和边界

保留原始 count cosine，新增 `log_count_cosine`，即对过滤后完整 barcode 的 reads 计数取 `ln(1+count)` 后计算余弦。没有出现在某文库的 barcode 权重为0，范数覆盖各文库全部达标 barcode，不是只在交集内归一化。空文库的相应指标为 null。

原始 cosine 对整体深度倍数缩放不变，log cosine 不具备这个性质；两者相关，不能解释成两项独立验证。log cosine 可以降低极端高丰度的支配，也可能提高广泛背景的相似度，因此不设自动通过阈值。

新增 Top 100 / 1000 / 10000 的 `abundance_overlaps[]`：按每文库计数确定边界，所有边界同分都纳入，附两边实际集合大小、交集和重合率。大量同分时实际集合可能远大于请求的Top数量；这是对不确定性的保留。原有 `top_barcode_overlap` 保持固定大小、按编码截断的旧定义，便于兼容，新增分层仅作解释，不参与排名投票。

每库新增 `abundance_tiers`（边界及实际数量）、`count_effective_barcodes`（总计数平方/计数平方和）和 `largest_barcode_read_fraction`。有效barcode数接近达标barcode数时，丰度趋于平坦；最大barcode占比高提示集中贡献。这些不是估计细胞数或测序饱和度。

## 多候选排名

log cosine 加入原有的覆盖率、Jaccard、raw cosine 共同领先规则。原始和log指向不同候选，返回 `conflicting_metrics`。没有任意权重或“饱和度大于某值就换算法”的切换。

旧代码的完全并列指标本来就是中性的：领先集合包含全部候选，不会排除任何候选。本次明确暴露这种行为：

- `informative_metrics`：领先集合未包含所有合格候选的指标，使用既有1e-12并列容差；不是统计显著性。
- `ranking_basis=abundance_only`：集合指标全并列，仅丰度指标有候选区分力。
- 其他依据为 `mixed_overlap_and_abundance`、`overlap_only`、`no_discriminating_metrics` 和 `descriptive_only`。
- `count_cosine_margin` / `log_count_cosine_margin`：该指标前两名差值，不是共同领先者的匹配置信度。

至少100个共有barcode的保护、部分扫描不选择优先候选、单候选无法确认等边界保持。单对会完整展示丰度证据，但仍为 `single_candidate_unresolved`；即使两种cosine都为1也不证明同一样本。尚未实现真实错配背景校准、Spearman排名相关或匹配概率。

## 资源和可复现性

按“不同reads计数值”缓存log权重，不额外为每个barcode保存一份浮点向量。log权重取1e9倍后四舍五入为整数，点积和范数平方用u128累加，避免HashMap遍历顺序与线程到达顺序改变浮点结果；相对直接log公式的误差由测试验证至1e-9量级。跨平台数学库最后位不作承诺。

Top边界复用原有有界堆的结果，不全量排序所有barcode。平坦计数的log点积、覆盖全库的Top集合交集可直接由共有barcode数推得，避免重复查表和判断。新指标仍有额外开销，不承诺相对v0.5更快。

## 验证

17项单元测试、11项CLI集成测试，clippy和fmt均通过。新增验证包括：

- 候选集合完全相同但高丰度分布不同：集合指标全为1，丰度指标正确区分相对候选。
- 集合与丰度均平坦一致：所有候选并列，无优先候选。
- raw与log指标冲突：不强行选择。
- log cosine与独立直接公式一致、对称性、空分母、深度倍数缩放的差异。
- Top100边界并列导致实际纳入120个；配套与错配的Top100重合分别为1和0，而Top1000均为1。
- 不同丰度数据下串行与并行除timings外逐字段完全一致；单对仍无法自动确认。

JSON schema升级为6，TSV新增 `log_count_cosine` 列。消费者需处理新字段、四个metric orders与新增排名依据。

合成基准原始记录见 `benchmarks/abundance-v0.6-results.json`。对照二进制为优化前v0.4，而非v0.5；每项前后交错重复3次，所有旧pair数值字段精确一致。数据热缓存、高压缩率、多样本同内容硬链接负载均不构成真实生物学验证。

Apple M3 / 16 GiB上的本轮实测示例（秒为外部进程墙钟中位数，MiB为峰值RSS最大值）：

| 负载 | 实际线程 | 秒：v0.4 → v0.6 | MiB：v0.4 → v0.6 |
|---|---:|---:|---:|
| 200万R1、每库20万barcode | 1 | 0.397 → 0.555 | 19.94 → 15.78 |
| 同上 | 2 | 0.218 → 0.213 | 23.67 → 19.39 |
| 360万R1、每库60万barcode | 1 | 0.803 → 0.775 | 70.98 → 53.98 |
| 200万R1、每库100万singleton | 1 | 0.656 → 0.531 | 138.94 → 104.95 |
| 16样本、256组合、320万R1 | 8 | 0.348 → 0.498 | 29.73 → 28.22 |

本轮部分情形耗时上升，尤其多样本新增丰度证据有实际成本；没有宣称整体提速。资源实测仍保留了此前内存优化的主要收益。
